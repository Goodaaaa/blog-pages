图解 HTTPS：一次握手到底握了什么

发布于 2026.10.22·更新于 2026.10.24

TLS 握手的目标只有一句话：在不安全信道上协商出只有通信双方知道的密钥。

TLS 1.3 的 1-RTT 握手

  1. Client Hello：带来随机数、密码套件列表与 key_share；
  2. Server Hello：选定套件、返回随机数与证书；
  3. 双方由 ECDHE 得到预主密钥，派生出对称会话密钥。

证书校验链

客户端逐级验证：域名匹配 → 有效期 → 信任链到根 CA → 吊销状态。任何一环失败即中断连接。

会话恢复（PSK）把 1-RTT 压缩为 0-RTT，但 0-RTT 数据有重放风险，只用于幂等请求。

小结

握手解决的是「密钥怎么安全送达」，真正的数据保护交给对称加密。理解了这一点，常见的 HTTPS 误解（如「HTTPS 就是加密」）都能拆开看。
